# ADR-0002：绑定采用点选式字段选择器，不提供表达式编辑器

- **日期**：2026-09-08
- **状态**：已接受
- **决策者**：项目所有者
- **相关**：`功能设计-v1.0.md` §4.3（lab 模块）

---

## 背景

0.01 的自编译模块平台提供 7 种模板形态与代码模式。模板模式的数据绑定字段为：

```js
edDraft = {
  bind: 'none',
  api: { url:'', path:'' },        // ← 手填 URL + JS 取值路径
  data: { source:'cpu', manual:50 },
  rows: '示例项目|值'
}
```

**三个真问题**（实勘结论）：

1. `api.path` 要求用户手写 `data.counts.posts` 这类取值路径 —— **这是代码，不是无代码**
2. 模板只能绑 8 个内置字段（FIELDS 字典），后端 18 个模块（文章/说说/相册/音乐/友链/收藏夹/访客/审核三类/系统/看板/配置…）**全部无法零代码接入**
3. 模板是只读展示，不能绑定写操作 —— 想做「待审评论一键通过」必须切代码模式

结果：名义上的"无代码模板模式"，实际 90% 需求仍要写代码。

## 决策

**绑定引擎采用点选式字段选择器，明确不提供表达式编辑器。**

1. **数据源注册表**：后端 18 个模块注册为可选数据源（含字段元数据），用户下拉选择，不手填 URL
2. **点选式字段选择**：拉取真实样例数据渲染预览，点击任意值即选中该字段；界面显示中文面包屑「评论 › 作者 › 登录名」，用户全程看不到点号路径
3. **格式化与变换全部走预设下拉**：数字/千分位/百分比/字节/时长/相对时间/枚举映射、取前 N/排序/筛选/去重/计数/求和
4. **动作绑定**：组件可绑写操作（审核通过/删除、开关切换、表单提交）
5. **代码模式保留**：`sandbox` iframe + `host.data` / `host.refresh()` 桥接口不变，作为逃生舱

## 备选方案

| 方案 | 否决理由 |
|---|---|
| 保留手填 `path`，加自动补全 | 仍是代码思维；用户要理解数据结构才能填，学习成本未降低 |
| 提供表达式编辑器（如 `{{item.views}}` 模板语法） | 灵活但门槛高；一旦开表达式，就会逐步演变成低代码平台，范围失控（R3） |
| 只做 7 模板迁移，绑定方式不变 | 等于把旧门槛原样搬进新架构，白重构一次 |
| 完全放弃代码模式 | 丢失 10% 的长尾能力与已有用户模块资产 |

## 理由

1. **用户诉求是"不需要代码就能快速绑定更多的东西"**，不是"更灵活的表达式"。点选式直接命中诉求。
2. **能力边界可锁死**：只有预设下拉，无表达式输入框 —— 这是防止范围蔓延的关键设计约束。
3. **可度量**：验收标准是「零代码新建待审评论模块 ≤ 60 秒」，表达式方案无法保证这个指标。

## 代价与风险

- 表达力受限：复杂数据整形做不了 → 由代码模式兜底（逃生舱）
- 路径解析需防注入：`resolve.js` 白名单 + 字符集校验 `[a-zA-Z0-9_.]`，拒绝 `__proto__` / `constructor`
- 数据源 Schema 需手工维护，可能与后端漂移（R13）→ 评估 `GET /api/_meta` 自动发现

## 验收方式

- 零代码完成「待审评论」模块（含通过/删除动作）≤ 60 秒
- 18 个数据源全部可零代码接入
- 0.01 的代码模式模块在 lab 中原样运行（桥接口不变）
- 恶意表达式被拒绝且有单测保护
