## 二、三条铁律（违反即打回，无例外）

1. **禁止改 `src/core/`** —— 内核是公共地基，改动需评审且要说明"为何不能由模块实现"（架构 §2 原则 1）。你的任务若需要改内核，先停下来在任务卡里说明，等确认。
2. **禁止向 `src/prototype.js` / `index.html` 添加业务逻辑** —— 它们已冻结，现有功能正在按领域迁入 `modules/site/`。新功能一律写成模块。
3. **DoD 没全勾 = 没完成**（`PROCESS.md` §3）。尤其是：代码提交了但没测试、改了逻辑没跑 `npm test`、`unmount` 没清理定时器——这三类直接打回。

## 四、任务 0 · 入职验证（约 30 分钟，所有人都从这里开始）

**目的**：验证你的环境能跑通全部检查，同时熟悉本项目最常用的 4 条命令。

```bash
git clone https://github.com/luoluo-C-N/luo.git
cd luo && git checkout develop
npm ci
npm test          # 期望：47/47 pass
npm run build     # 期望：Built 29 static assets
npm run smoke     # 期望：6 项 PASS（自动起服务，无需先开 dev server）
```

**交付**：把三条命令的最后 10 行输出贴到任务回执。
**任何一条失败**：停下报告，不要自行改配置绕过——失败本身就是需要记录的信息。

## 五、任务 1 · 第一个真实任务（site 迁移规划，约 2–4 小时）

> 内核（`src/core/`）正由另一会话建设中，**此任务不写代码、不碰内核**，零冲突。

**任务卡**

```
## [T-SITE-PLAN] site 模块迁移拆分方案
- 优先级：P0
- 规模：M（2-4h）
- 前置：完成任务 0

### 验收标准
- Given 功能设计-v1.0.md §4.1 与 现有 src/prototype.js（3553 行）
- When 按"单文件 ≤300 行"约束规划迁移
- Then 产出 docs/plans/site-migration.md，包含：
  1. modules/site/ 下的完整文件清单（views/ data/ 各文件职责一句话）
  2. 每个文件对应 prototype.js 的行号区间（源 → 目标映射表）
  3. 迁移顺序（哪个先迁、依赖关系）
  4. 每步的验证方式（迁移后如何证明"功能等价且视觉零差异"）
  5. 风险清单：哪几处最可能在迁移中出 bug（结合 20 处硬编码地址、
     同名函数覆盖、全局状态等已知问题）

### 明确不做
- 不写任何代码；不修改 src/core/
```

**为什么先做规划**：这是 3,553 行单体的拆解，方案错了返工的是全部。规划先行是本项目从 0.01 学到的最贵一课（QA 计划写了 36 项没执行，就是没先规划顺序）。
