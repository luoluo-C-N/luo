# 掌上小站真机产品验收与集中修复设计

## 目标

以产品经理和测试负责人视角，对“掌上小站”Android 客户端进行一次完整、可复现的真机验收，形成问题清单，集中修复高优先级与可确认问题，完成回归并交付新的 debug APK。

## 测试环境

- 测试设备：vivo V2068A，Android 11，720×1600，arm64-v8a。
- 设备通过 USB Debug/ADB 连接，由自动化脚本安装 APK、启动应用、执行点击和滑动、截屏、读取日志及性能数据。
- 使用 8011 端口的隔离后端和独立 fixture 数据库执行增删改查、审核、上传和删除测试。
- 正式 8000 后端只做健康检查和公开只读检查，不执行破坏性验证。
- App 测试连接地址使用电脑局域网地址 `http://192.168.10.83:8011`。

## 验收范围

### 产品与信息架构

- 首次启动、连接设置、登录、游客模式和退出登录。
- 看板、内容、状态、审核、我的五个主导航区域。
- 侧栏、子页面、返回路径、空状态、加载状态、错误状态和成功反馈。
- 文案是否准确，演示数据是否可能被误认为真实数据。

### 功能闭环

- 文章：列表、搜索、分页、新建、草稿、编辑、发布和删除。
- 说说、相册、照片、分类、标签、项目、友链、收藏夹与访客管理。
- 评论、留言和说说评论审核。
- 图片和音乐上传、编辑、排序、播放和删除。
- 连接设置、个人资料、主题、壁纸、面板与自定义模块。

### 真机交互与兼容性

- 点击热区、纵向滚动、横向滑动、侧栏、返回键和弹窗。
- 软键盘出现/隐藏、输入框聚焦、长列表滚动和文件选择。
- 安全区、状态栏、导航栏、横竖屏策略、后台恢复与重新启动。
- 断网、错误地址、后端超时、401/403/404/409/500 等异常反馈。

### 性能与稳定性

- 冷启动和页面切换响应。
- 侧栏、滚动和弹窗动画的卡顿情况。
- Android `logcat` 中的崩溃、WebView、网络和 JavaScript 错误。
- `dumpsys gfxinfo` 帧耗时、内存占用和重复操作后的稳定性。

## 问题分级

- P0：崩溃、数据破坏、安全问题、无法进入应用。
- P1：主流程不可用、无法登录、无法保存、导航或返回失效。
- P2：明显卡顿、布局遮挡、反馈错误、次要功能不可用。
- P3：文案、视觉一致性和低影响体验问题。

P0/P1 必须修复；P2 原则上本轮修复；P3 在不扩大架构和视觉范围时一并处理，其他项目进入后续清单。

## 修复策略

- 每个可复现缺陷先保存证据，再建立最小回归测试。
- 修复源头文件和工程拆分产物，避免下次同步覆盖。
- 每轮执行单元测试、静态构建、运行时冒烟和 Android 构建。
- 安装新 APK 后重新执行对应真机场景，并对主流程做一次完整回归。
- 不做与问题无关的大规模重构；对阻碍稳定性的单文件耦合只做必要拆分。

## 交付物

- 按优先级整理的问题与处理结果。
- 自动化回归测试和必要的真机验收脚本。
- 更新后的源码、构建产物和签名验证记录。
- 最新 debug APK、SHA-256 和剩余限制说明。

## 完成标准

- 手机可以稳定安装、启动、连接隔离后端并登录。
- 五个主导航和关键 CRUD/审核/上传流程可完成。
- 不存在已知 P0/P1；本轮可复现的 P2 已处理或明确记录阻塞原因。
- 侧栏、页面滚动、返回和弹窗不残留半开或不可操作状态。
- 自动化测试、构建、运行时冒烟和 APK 签名验证通过。
- 正式数据未被测试写入或删除。
