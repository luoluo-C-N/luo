# 掌上小站 · 开发流程规范

> 维护人：PM · 建立日期：2026-09-08 · 适用：v0.02 起
> 与 `架构设计-v1.0.md` §14 协作规范配套使用，本文档补充**可执行的细则与模板**。

---

## 1. 分支策略

```
main        受保护，永远可发布。禁止直推，仅接受 PR
develop     集成分支（当前 HEAD）
feat/<id>   功能模块分支，如 feat/lab、feat/site-migrate
fix/<描述>   缺陷修复
```

**规则**：一个模块一个分支；PR 合并后删除分支；`main` 需 CI 全绿 + 至少一人 review。

---

## 2. 提交规范（Conventional Commits）

```
<type>(<scope>): <subject>

type:  feat | fix | docs | refactor | test | chore | perf | build
scope: core | site | task | lab | game | remind | album | password | wallet | docs | ci
```

**示例**：
```
feat(lab): 新增点选式字段选择器
fix(core): 容器卸载未清理定时器
refactor(site): 内容 CRUD 改为数据源 Schema 驱动
chore: 建立 v0.01 基线
```

**禁止**：`更新` `修改` `fix bug` 等无信息量的提交信息。

---

## 3. 完成定义（DoD）—— 每个任务完成前逐条打勾

```
- [ ] 代码已提交，符合 Conventional Commits
- [ ] npm test 通过
- [ ] npm run build 通过
- [ ] npm run smoke 通过
- [ ] 契约测试 17/17（触碰后端时）
- [ ] 新增/修改逻辑有对应测试（禁止只改代码不加测试）
- [ ] 无硬编码地址（统一走 ctx.net）
- [ ] 错误态已处理，未用演示数据冒充在线数据
- [ ] 模块样式带 .mod-{id} 前缀
- [ ] unmount() 已清理定时器与事件监听
- [ ] 协作日志已追加「完成回执」，含改动文件清单
```

**未全勾 = 未完成。**

## 5. 异步站会模板

每次会话结束前写入 `docs/standup/YYYY-MM-DD-<角色>.md`：

```markdown
# 站会 · YYYY-MM-DD · <角色/会话标识>
昨日完成：<一句话 + 关联 commit>
今日计划：<一句话>
阻塞：<无 / 描述 + 需要谁的输入>
风险信号：<新发现的问题>
```

> 目录 `docs/standup/` 已在 `.gitignore` 中忽略（避免噪音），但本地保留供会话间交接。

---

## 6. 会话交接模板（多智能体/多会话必用）

```markdown
## 交接 · <角色> · <时间>
已完成：<文件清单 + 验证命令 + 结果>
进行中：<任务 + 剩余步骤>
阻塞：<问题 + 需要的输入>
下一步建议：<一句话>
```

**命名规范**：禁止多个同名会话。必须带作用域，如 `ZCode-后端` / `ZCode-原型` / `ZCode-PM`。

## 7. 代码评审清单

**内核（`src/core/`）改动必查**：
- [ ] 是否真的不能由模块实现？（架构 §2 原则 1）
- [ ] 是否引入了对具体模块的依赖？
- [ ] 是否有至少一人 review？

**模块改动必查**：
- [ ] 是否 `import` 了其他模块内部文件？（禁止，走 bus）
- [ ] 是否用了裸 `localStorage` / 裸 `fetch` / `window.xxx`？
- [ ] `permissions` 声明是否与实际使用一致？
- [ ] 声明 `vault` 是否实现了 `onLock`？

**安全相关（`*auth*` `*vault*`）必查**：
- [ ] 敏感数据是否落盘即密文？
- [ ] 是否写入了日志或错误上报？
- [ ] 锁定后内存密钥是否清零？

## 8. 阶段门检查单

### G1 发布门（构建/发布 APK 前）

- [ ] 工作区 clean，从干净状态构建
- [ ] npm test / build / smoke / 契约 全绿
- [ ] **APK 构建时间戳 > 最后一次源码 mtime**（防 01:37 事件重演）
- [ ] SHA256 已生成并记录
- [ ] CHANGELOG 已更新，版本号三处一致（package.json / versionName / 文件名）
- [ ] 已知限制已写入 release notes
- [ ] git tag 已打

### G2 生产数据门（任何触碰 8000/生产库的操作前）

- [ ] 是否已确认无法在 8011 隔离环境完成？
- [ ] 生产库备份是否已生成并验证可还原？
- [ ] 操作命令是否已由第二人复核？
- [ ] 是否只读？若非只读，是否已获明确授权？
- [ ] 回滚方案是否已就绪？

## 9. 事故管理

```
SEV1  生产数据丢失 / 安全漏洞    → 立即停手，2h 内报告，24h 内复盘
SEV2  主流程不可用 / 构建失败    → 当日修复，当周复盘
SEV3  次要功能 / 体验问题        → 纳入迭代待办
```

复盘报告写入 `docs/postmortem/`，模板见 §10。

---

## 10. 事故复盘模板

```markdown
# 事故复盘 · <日期> · <一句话标题>

## 1. 时间线（分钟级）
## 2. 影响范围（数据 / 功能 / 用户）
## 3. 根因（5-Why）
## 4. 纠正措施（每项含 owner + 截止日 + 验收方式）
## 5. 预防措施（流程 / 工具 / 门禁）
```
