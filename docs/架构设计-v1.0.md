# 掌上小站 · 个人超级 App 架构设计 v1.0

> **状态**：待评审 · **适用版本**：v0.02 起 · **读者**：全体开发协作者
> **定位**：仅为自己所用的个人集合 App / 数字遗产。网站管理只是其中一个模块。
> **前置阅读**：`docs/api-contracts.md`（后端契约）、`docs/design-0.01.md`（0.01 需求）

---

## 0. 一句话

**内核只做四件事（注册 / 路由 / 能力 / 安全），一切功能皆模块，模块之间零耦合，敏感数据走加密地基。**

---

## 1. 为什么重写架构（现状问题）

| 问题 | 证据 | 后果 |
|---|---|---|
| 全局命名污染 | `src/prototype.js` 内 `var API_BASE`、`window.jumpTab`、`window.fetchSystemStatus` 等 | 功能加到第 N 个必撞名 |
| 样式无隔离 | 全部共用 `src/prototype.css`（626 行） | 小游戏的 `.card` 污染钱包的 `.card` |
| 页面硬编码 | `index.html` 777 行写死 5 Tab + 17 子页 | 每加功能改一次，越改越脆 |
| 存储无分层 | 全部裸 `localStorage`（`panelPins`/`panelSkins`/`pocket.server`） | 密码、钱包明文 = 丢手机全泄露 |
| 无模块生命周期 | 脚本一次性同步执行 | 单模块报错 → **整 App 白屏**（当前 P0 正是此形态） |
| 硬编码后端地址 | `prototype.js` 约 20 处 `http://localhost:8000` | 真机上请求全部失效 |

**结论**：不是"少做功能"，而是"换骨架"。模块隔离后，单模块崩溃只降级该模块，不再白屏。

## 2. 设计原则

1. **内核极简**：内核只认识"模块"，永不写业务代码。判断标准——新需求若让内核改动，说明设计错了。
2. **模块零耦合**：模块之间禁止直接 import，只能通过内核能力 API 与事件通信。
3. **故障隔离**：任一模块加载/运行失败，只降级该模块并在导航标记，其余照常。
4. **本地优先，云端可选**：所有模块离线可用，同步是增强不是依赖。
5. **敏感数据默认加密**：钱包、密码库等声明 `vault` 权限的模块，数据一律密文。
6. **可导出**：任何模块数据可加密导出为单文件——这是"数字遗产"的底线。

```
┌─ 模块层 ───────────────────────────────────────┐
│  site(网站管理) · task · game · remind          │
```

## 5. 内核设计

### 5.1 registry.js — 模块注册

```js
/**
 * @typedef {Object} ModuleManifest
 * @property {string} id          全局唯一，小写字母，如 'wallet'
 * @property {string} name        显示名
 * @property {string} icon        单个 emoji 或图标 key
 * @property {string} version     语义化版本
 * @property {'tab'|'tool'|'hidden'} nav  导航形态
 * @property {number} [order]     排序，默认 100
 * @property {string[]} [permissions]  'storage'|'net'|'notify'|'vault'|'files'
 * @property {(ctx:ModuleContext)=>void|Promise<void>} mount
 * @property {()=>void} [unmount]
 * @property {(ctx:ModuleContext)=>void} [onShow]
 * @property {()=>void} [onHide]
 */
```

职责：
- 校验 manifest 必填字段与权限合法性（声明 `vault` 的模块必须实现 `onLock`）
- 维护模块表，支持运行时注册（热插拔）
- **注册失败不影响其他模块**：捕获异常并标记为 `broken`

### 5.2 router.js — 路由与容器

- 每个模块挂载到一个独立容器 `<section class="module" data-module="wallet">`
- 切换 Tab = 卸载上一个容器 + 挂载下一个（调用 `unmount`/`onHide`）
- **容器级隔离**：模块 DOM 全在自己的容器内，卸载即清空
- 导航项由 registry 动态生成，`index.html` 不再硬编码 Tab

### 5.3 capabilities.js — 模块唯一入口

```js
/** @typedef {Object} ModuleContext
 * @property {string} id
 * @property {{get(k):Promise<any>, set(k,v):Promise<void>, remove(k):Promise<void>}} store
 * @property {{request(path,opts):Promise<any>, base():string}} net
 * @property {VaultApi|null} vault        仅 permissions 含 'vault' 时注入
 * @property {{toast(t):void, confirm(t):Promise<boolean>, card(html):Element}} ui
 * @property {{schedule(opt):Promise<void>, cancel(id):Promise<void>}} notify
 * @property {{on(evt,fn):void, emit(evt,data):void}} bus
 */
```

**关键约束**：`ctx.store` 自动加命名空间前缀 `mod:{id}:`，模块之间**不可能**互相覆盖数据。

### 5.4 vault.js — 安全加密

见第 8 节。

### 5.5 启动流程

```
core/index.js
  → 读取已启用模块列表（Preferences）
  → 逐个 import manifest（失败则标记 broken，继续）
  → 权限校验 → 注入 ctx
  → 渲染导航（broken 模块显示为"不可用"而非隐藏）
  → 挂载默认模块
```

## 6. 模块规范（团队开发必读）

### 6.1 最小可用模块

```js
// src/modules/task/manifest.js
export default {
  id: 'task',
  name: '今日任务',
  icon: '✅',
  version: '0.1.0',
  nav: 'tab',
  order: 10,
  permissions: ['storage'],
  async mount(ctx) {
    const list = (await ctx.store.get('items')) || [];
    const root = ctx.ui.card(`<h3>今日任务</h3><ul>${
      list.map(t => `<li>${ctx.ui.esc(t.title)}</li>`).join('')
    }</ul>`);
    document.querySelector(`[data-module="task"]`).append(root);
  },
  unmount() { /* 清理定时器、事件监听 */ }
};
```

### 6.2 强制约定

| 约定 | 说明 |
|---|---|
| 样式前缀 | 模块 CSS 所有选择器必须带 `.mod-{id}` 前缀，如 `.mod-wallet .card` |
| 禁止全局 | 严禁 `window.xxx =`、严禁裸 `localStorage`、严禁裸 `fetch` |
| 只用 ctx | 网络走 `ctx.net`，存储走 `ctx.store`，通知走 `ctx.notify` |
| 必须清理 | `unmount()` 内清除定时器与监听器，否则内存泄漏 |
| 声明权限 | 用到什么能力就在 `permissions` 声明，未声明的能力 ctx 中不存在 |

### 6.3 模块间通信

**唯一方式**是事件总线：

```js
ctx.bus.emit('site:pending-changed', { count: 3 });
ctx.bus.on('site:pending-changed', ({ count }) => { /* ... */ });
```

禁止 `import` 其他模块的内部文件。

## 7. 数据层

| 层 | 技术 | 用途 | 示例 |
|---|---|---|---|
| 配置 | `@capacitor/preferences` | 小键值 | 模块启用状态、主题 |
| 结构化 | SQLite（`@capacitor-community/sqlite`） | 数据量大时 | 任务、账单流水 |
| 文件 | `@capacitor/filesystem` | 图片、附件、导出包 | 图床缓存、加密备份 |
| 加密 | `core/vault.js` + 上述任一载体 | 密码、钱包 | 密文落盘 |
| 同步 | 后端 Kirameku 扩展（待定） | 多设备 | 增量同步 |

**命名空间**：`mod:{moduleId}:{key}`，模块无法越界读写。

**当前阶段建议**：v0.02~0.04 只用 `Preferences` + 加密 JSON；等单模块数据超过 ~1MB 或需要复杂查询时再引入 SQLite，避免过早复杂化。

## 8. 安全设计（密码库 / 钱包）

### 8.1 密钥派生

```
主密码（用户记忆，永不落盘）
   │ PBKDF2-SHA256 · 600,000 次迭代 · 16 字节随机盐
   ▼
KEK（密钥加密密钥，仅内存）
   │ AES-GCM 解密
   ▼
DEK（数据加密密钥，加密后存 Preferences）
   │ AES-GCM · 每条记录独立 IV
   ▼
明文数据（仅内存，落盘即密文）
```

使用 `WebCrypto`（`crypto.subtle`），不引入第三方加密库。

### 8.2 硬性约束（Code Review 检查项）

1. 主密码**不落盘**，只保存用于校验的派生值
2. 密钥仅存在于内存变量，App 退后台 **5 分钟**自动锁定并清零
3. 声明 `vault` 的模块进入时**默认要求重新校验**（即使 App 已解锁）
4. 生物识别（指纹/人脸）仅解锁本地 KEK，**不做云端认证**
5. 提供**一键加密导出**：单文件 + 主密码，可离线恢复
6. **禁止**把敏感数据写入日志、错误上报、截屏缓存

### 8.3 ⚠️ 必须同步收紧的现有配置

`capacitor.config.json` 当前为：

```json
"server": { "androidScheme": "http", "cleartext": true },
"android": { "allowMixedContent": true }
```

**在引入密码库/钱包之前必须改为**：关闭 `cleartext` 与 `allowMixedContent`，后端启用 HTTPS，否则加密存储会被明文传输通道抵消。此项计入 v0.03 的准入条件。

### 8.4 威胁模型（明确不做）

- ✅ 防：设备丢失后的离线暴力破解（PBKDF2 高迭代 + 自动锁定）
- ✅ 防：模块越权读取其他模块数据（命名空间 + 权限声明）
- ❌ 不防：设备已被 root 且运行时内存被读取
- ❌ 不防：主密码被肩窥或社工获取
- ❌ 不做：云端托管主密码（一旦做，就不是"仅为我所用"）

## 9. UI 与设计系统

- `src/ui/tokens.css` 定义颜色/间距/圆角/字号变量，模块**只能引用变量**，禁止硬编码色值
- 毛玻璃等视觉规范沿用 `E:\glm\ui-design\管理App设计规范.md` 第 6 节
- `context.ui` 提供基础组件（卡片、按钮、输入、弹层），模块优先复用而非自造
- 深色模式由内核统一切换，模块通过 CSS 变量自适应，不得自行实现

## 10. 新增模块 SOP（以「今日任务」为例）

1. 建目录 `src/modules/task/`，新建 `manifest.js` / `index.js` / `style.css`
2. 在 `src/core/index.js` 的模块清单中加入 `import task from '../modules/task/manifest.js'`
3. 实现 `mount(ctx)`，所有 DOM 挂到 `[data-module="task"]` 容器
4. 样式全部加 `.mod-task` 前缀
5. 写单测 `tests/modules/task/index.test.mjs`
6. 本地 `npm run dev` 验证：加载、卸载、退后台再进入、与其他模块并存
7. 提交 PR，**不改动任何 `src/core/` 以外不属于你的文件**

验收标准：模块崩溃时 App 其余部分可用；卸载后无残留定时器。

| 现状 | 去向 |
|---|---|

## 14. 协作规范

1. **分支**：`main` 受保护；开发用 `feat/<module-id>`，PR 合并
2. **模块所有权**：每个模块在本文档附录登记负责人，**同一时间只允许一人写**
3. **内核改动**：`src/core/` 任何改动需至少一人 review，且必须说明"为何不能由模块实现"
4. **提交信息**：`feat(wallet): 新增账单流水`、`fix(core): 容器卸载未清定时器`
5. **单一写者**：延续 0.01 规则，改共享文件前在协作区声明
6. **禁止回退**：新代码禁止再向 `prototype.js` / `index.html` 添加业务逻辑
