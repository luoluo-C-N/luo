## 2. 内核功能规格

> 内核也是产品。用户能看见、能用的内核能力，必须在这里定义清楚。

### F-K1 启动与模块加载

| 项 | 规格 |
|---|---|
| 启动画面 | 内核启动 ≤ 300ms 内出骨架，模块异步挂载，不阻塞首屏 |
| 加载失败 | 失败模块在导航标记为「⚠️ 不可用」，**可点击查看错误摘要**，其余模块照常 |
| 空状态 | 零模块时不白屏，展示「还没有模块，去模块中心开启」引导 |
| 首次启动 | 引导：设置后端地址（可跳过）→ 选择要启用的模块 → 完成 |

**验收标准**：
- 人为让 `site.mount()` 抛错，App 其余模块可用，导航出现⚠️标记且不崩溃
- 冷启动到可交互 ≤ 1.5s（vivo V2068A 实测）

### F-K2 导航

架构 §5.2 定义容器挂载，此处定义**用户看到的形态**：

| nav 形态 | 呈现 | 用途 |
|---|---|---|
| `tab` | 底部导航栏条目，最多 5 个，超出收进「更多」 | 高频主功能：site / task / remind |
| `tool` | 「我的 → 工具」区九宫格入口 | 中频：album / password / wallet / game / lab |
| `hidden` | 无入口，仅被其他模块唤起或事件触发 | 后台能力、实验功能 |

**多面板工作台的处理**（架构 §11 说"重定位为内核导航容器的 UI 层"——此处明确）：

> 现有「面板 = 独立导航体系」概念，**降级为用户可创建的导航分组**。内核只认模块与 Tab；面板是一层可选的视觉分组壳，由内核提供、不进模块层。
> 即：面板不再是架构概念，而是导航的展示选项（默认关闭，开启后在 Tab 上方显示分组切换条）。

**理由**：架构 §2 原则 1 要求内核极简。让内核理解"面板拥有独立导航体系"会让内核承担业务语义，且现有实现正是 `prototype.js` 复杂度来源之一。**建议接受此降级**，若你坚持保留多套导航体系，需在架构文档补充说明并扩 `nav` 枚举。

### F-K3 模块中心

| 功能 | 规格 |
|---|---|
| 列表 | 全部已注册模块（含未启用），显示 图标/名称/版本/状态/占用 |
| 启停 | 启用后按 `nav` 形态出现在对应入口；停用保留数据 |
| 排序 | Tab 顺序与工具区顺序可调，持久化到内核配置 |
| 权限透明 | 每个模块详情页列出其声明的权限及用途说明（用户可读） |
| 故障可见 | broken 模块显示错误摘要 + 「重试加载」按钮 |
| 存储占用 | 显示每模块数据量，提供「清理数据」（二次确认） |

**验收标准**：停用再启用 task 模块，数据完整保留；拒绝授予 `net` 的模块无法发起网络请求（ctx 中无 `net`）。

### F-K4 设置中心

| 分组 | 项 |
|---|---|
| 外观 | 深色模式、毛玻璃质感（透明度/模糊，沿用现有双滑杆）、壁纸（6 预设 + 自定义 ≤8 张）、背景模糊/纱度 |
| 连接 | 后端地址（替代现有 `localStorage.setItem('pocket.server', …)` 的手工操作）、连接测试、超时设置 |
| 实验室 | 实验功能开关（灰度用），标注「可能不稳定」 |
| 关于 | 版本、模块清单、开源许可、构建时间 |

**验收标准**：改后端地址后全部模块立即生效，无需重启；地址非法时给出明确错误（不是静默失败）。

### F-K5 数据管家

| 功能 | 规格 |
|---|---|
| 单模块导出 | 任一模块导出为 `.json`（敏感模块强制加密） |
| 全量导出 | 单文件 `pocket-backup-YYYYMMDD.pkt`，可选主密码加密 |
| 导入 | 覆盖/合并二选一，导入前自动备份当前数据 |
| 迁移 | 检测旧版 `localStorage` 散落键（现有 6 个：`customModules`/`customPanels`/`panelPins`/`panelOrder`/`panelSkins`/`renameNames`），一次性转为 `mod:site:*` 命名空间，转换前备份 |

**验收标准**：导出后再导入，数据往返一致；导入失败可回滚到导入前快照。

### F-K6 安全中心（v0.03）

| 功能 | 规格 |
|---|---|
| 主密码 | 首次设置需二次确认 + 强度提示；**遗忘无后路**，强制引导生成加密导出包 |
| 自动锁定 | 退后台 5 分钟锁定；可配置 1/5/15 分钟 |
| 生物识别 | 指纹/人脸仅解锁本地 KEK，失败回落主密码 |
| 锁定态 | vault 模块显示锁定占位，非 vault 模块不受影响 |
| 修改主密码 | 需校验旧密码，用新 KEK 重封 DEK（不重加密业务数据） |

**验收标准**：锁定后内存中的 KEK/DEK 已清零（断言不可读）；修改主密码后原数据仍可解密。

## 3. 能力 API 的功能行为（ctx 语义）

架构 §5.3 定义了接口签名，此处定义**运行时行为**——模块作者需要知道"调用后会怎样"。

| 能力 | 行为约定 |
|---|---|
| `ctx.store` | 自动前缀 `mod:{id}:`；返回 Promise；写入失败（配额满）抛出明确错误而非静默丢弃；vault 模块额外提供 `ctx.store.secure` 走加密区 |
| `ctx.net` | 统一走内核配置的地址，**模块永远不拼绝对 URL**；超时默认 15s；401 触发内核统一登出流程；失败返回结构化错误 `{code, message, cause}`，**禁止回退演示数据** |
| `ctx.ui` | `toast` 1.8s 自动消失；`confirm` 返回 Promise<boolean>；`card(html)` 返回已套用毛玻璃配方的元素；`esc()` 必须用于所有用户输入 |
| `ctx.notify` | 封装 LocalNotifications；申请权限时机由内核统一；用户拒绝后模块不得反复弹权限 |
| `ctx.vault` | 仅 `permissions` 含 `vault` 时存在；`unlock()` / `lock()` / `encrypt()` / `decrypt()`；模块进入默认要求重新校验 |
| `ctx.bus` | 事件名必须 `<moduleId>:<event>` 前缀；内核不保证跨会话持久；`on` 返回退订函数，`unmount` 必须调用 |

**统一错误行为**（架构 §5.6 errors.js 的功能侧）：
- 模块内未捕获异常 → 内核捕获 → 标记该模块为 `degraded` → toast「XX 模块出现问题，已隔离」→ 其余不受影响
- 网络失败 → 模块自行决定展示，但**不得用演示数据冒充在线数据**（0.01 已确立原则，继续强制）

### 4.1 `site` · 网站管理

**定位**：唯一的存量模块，也是架构的**验证场**。它要证明：3,553 行单体拆成模块后，功能不丢、观感不变、崩溃可隔离。

```js
// src/modules/site/manifest.js
export default {
  id: 'site',
  name: '网站',
  icon: '🌐',
  version: '0.2.0',
  nav: 'tab',
  order: 10,
  permissions: ['storage', 'net'],
  mount, unmount, onShow, onHide
};
```

#### 功能清单（迁移自现有实现，逐项对齐）

| ID | 功能 | 现状 | 迁移要求 |
|---|---|---|---|
| SITE-FR1 | 服务器状态：CPU/内存/磁盘、服务状态、开放端口、流量 | 已有 | 15s 轮询，失败显示 `—` |
| SITE-FR2 | 看板：三格统计、快捷入口、趋势图、待办、分区开关 | 已有 | 待办点击跳审核分段 |
| SITE-FR3 | 内容：文章/说说/音乐/相册 四段 CRUD | 已有（`CRUD_DEFS` 九类） | **改为数据源 Schema 驱动** |
| SITE-FR4 | 审核：评论/留言/说说评 三类 + 子级内联审核 | 已有 | 通过/删除真实生效 |
| SITE-FR5 | 文章编辑器：Markdown 工具栏 + 草稿/发布 | 已有 | 401 保留未提交草稿 |
| SITE-FR6 | 我的：资料、站点管理、通用、账号 | 已有 | 通用设置移交内核 F-K4 |
| SITE-FR7 | 待审数变化广播 | 新增 | `emit('site:pending-changed', {count})` |

#### 拆分要求（架构 §11）

`prototype.js` 3,553 行按领域拆入 `modules/site/`，**单文件 ≤ 300 行**：

```
modules/site/
  manifest.js  index.js  style.css
  views/   status.js  dashboard.js  content.js  audit.js  profile.js  editor.js
  data/    sources.js（数据源 Schema）  api.js（契约适配）
```

#### 数据模型

```
mod:site:config        后端地址、分段偏好
mod:site:drafts        未发布草稿（含失败保留）
mod:site:cache         最近一次成功的状态/看板数据
mod:site:rename        重命名体系（导航/区块）
```

#### 事件

| 事件 | 载荷 | 订阅方 |
|---|---|---|
| `site:pending-changed` | `{count, byType:{comments,messages,chatters}}` | remind（提醒）、内核（角标） |
| `site:auth-expired` | `{}` | 内核（统一登出） |

#### 验收标准

1. 与 v0.01 **功能等价且视觉零差异**（并排截图比对）
2. 九类资源增改删往返通过；契约测试保持 17/17
3. **全模块消灭 20 处硬编码 `http://localhost:8000`**（`grep -c "localhost:8000" src/` = 0）
4. `site.mount()` 抛错时，其余模块与导航正常
5. 401 时保留未提交草稿；网络失败不显示演示数据

#### 明确不做

多站点管理、前台页面编辑、SEO 工具、WebHook 配置（0.01 设计文档 §3 提到但未实现，不在本期）。

### 4.3 `lab` · 自编译工作台

**定位**：把 0.01 的"自编译模块平台"升级为**零代码绑定工作台**。这是你上一轮提的核心诉求，在本架构下重定位为独立模块。

```js
export default {
  id: 'lab', name: '实验室', icon: '🧪', version: '0.1.0',
  nav: 'tool', order: 60, permissions: ['storage', 'net'],
  mount, unmount
};
```

#### 核心问题（为什么要重新设计）

现有绑定模型要求用户手填 `api.path`（如 `data.counts.posts`）——**这是代码，不是无代码**；模板只能绑 8 个内置字段，后端 18 个模块接不进来；模板只读，不能绑写操作。

#### 功能清单

| ID | 功能 | 说明 |
|---|---|---|
| LAB-FR1 | 数据源注册表 | 后端 18 个模块注册为可选数据源（含字段元数据） |
| LAB-FR2 | 三步绑定向导 | ①选数据源 → ②点选字段 → ③选形态调样式 |
| LAB-FR3 | 点选式字段选择器 | 拉取真实样例数据渲染预览，**点击任意值即选中该字段**，界面显示中文面包屑「评论 › 作者 › 登录名」 |
| LAB-FR4 | 格式化预设 | 数字/千分位/百分比/字节/时长/相对时间/日期模板/枚举映射/前后缀/截断/空值兜底 |
| LAB-FR5 | 变换预设 | 取前 N/排序/筛选/去重/计数/求和/平均/分组计数 |
| LAB-FR6 | 动作绑定 | 组件可绑写操作：审核通过/删除、开关切换、表单提交 |
| LAB-FR7 | 组件库 | 13 种：数值/进度/状态/开关/列表/表格/图表/画廊/表单/审核队列/播放器/动态流/嵌入 |
| LAB-FR8 | 布局编排 | 12 栅格，拖拽换位 |
| LAB-FR9 | 代码模式（保留） | sandbox iframe + `host.data` / `host.refresh()` 桥接口**完全不变**，作为逃生舱 |
| LAB-FR10 | 分享码 | 模块级导出/导入；v0.05 增加面板模板（整包） |

#### 绑定三步流程（界面）

```
① 选数据源   18 个已注册 · 可搜索 · 可加筛选条件
      ↓
② 点选字段   真实数据预览 → 点击选中 → 中文面包屑确认
      ↓
③ 选形态     13 组件宫格 + 图标/颜色/尺寸 + 格式化 + 刷新策略
```

**耗时目标：零代码新建「待审评论」审核模块 ≤ 60 秒。**

#### 数据模型

```
mod:lab:widgets     组件实例与绑定配置
mod:lab:sources     自定义数据源（用户新增的 API）
mod:lab:layout      布局与所属容器
```

#### 验收标准（★ 核心）

1. **零代码完成"待审评论"模块（含通过/删除动作）≤ 60 秒**
2. 18 个数据源全部可零代码接入
3. v0.01 的代码模式模块在 lab 中原样运行（桥接口不变）
4. 路径解析拒绝恶意表达式（`__proto__`、`constructor`）
5. 单组件崩溃不影响同页其他组件

## 5. 跨模块协作契约

### 5.1 事件命名

`<moduleId>:<event-name>`，全小写，中划线分词。**跨模块事件必须登记在此表**，未登记的事件视为模块内部实现。

| 事件 | 发出方 | 载荷 | 订阅方 | 用途 |
|---|---|---|---|---|
| `site:pending-changed` | site | `{count, byType}` | remind、内核 | 待审数变化 → 提醒与角标 |
| `site:auth-expired` | site | `{}` | 内核 | 统一登出 |
| `album:uploaded` | album | `{url, orientation}` | site | 文章编辑器插图 |
| `vault:locked` | 内核 | `{}` | password、wallet | 锁定态切换 UI |
| `vault:unlocked` | 内核 | `{}` | password、wallet | 恢复展示 |

### 5.2 场景示例

**场景：有待审评论时收到提醒**

```
site 轮询审核接口 → 数量变化
  → emit('site:pending-changed', {count:3})
  → remind 已订阅 → 比对用户阈值 → ctx.notify.schedule()
  → 内核 更新 Tab 角标
```

三个模块零 import，任一崩溃不影响其余。

沿用 `E:\glm\ui-design\管理App设计规范.md`，此处仅列模块必须遵守的**功能级**约束：
